# 서론

  

맥에서 이클립스를 사용하려면 불편함을 감수해야 하는 부분이 있는데, 그중에서도 제일은 `한글 짤림` 현상일 것입니다. 이것은 한글 타이핑 시 마지막에 입력한 글자가 지워지는 현상이므로, 이를 방지하려면 문장 작성 후 esc, enter, space 키 등을 입력해 주어야 하는 번거로움이 있습니다. (SQL 클라이언트 툴인 `Dbeaver` 도 동일한 증상을 지니고 있습니다.)

![](https://i.imgur.com/vo4hEZj.gif)


구글 검색을 해보니 2013년 이전부터 리포팅되어 왔지만 프로그램 개선이나 해결책 없이 방치된 문제로 보였습니다. 여러 포스팅에서 `맞춤법 자동 수정` 을 해제하라는 말이 있었지만 일단 현재 기준으로는 전혀 효과가 없었습니다.

  

결국 개인적인 시행착오 끝에 `Karabiner-Elements` 를 활용하여 불편함을 어느 정도 해소할 수 있는 방법을 찾아보았습니다.

  

바쁘신 분들은 아래의 적용 방법 부분만 확인하시길 바랍니다.

# 원인 분석

  

추측건대 한글은 자모를 조합하여 문자가 되는 특성 때문에 영어처럼 바로 입력되지 않고, 문자가 완성될 때까지 임시 공간에 있다가 에디터가 문자 완성을 판단하는 시점에 비로소 입력되는 것으로 보입니다. 다른 에디터와 비교했을 때 이클립스는 이 판단을 깊이 있게 고려하지 않은 듯합니다. ~~대충 이클립스가 판단력이 나쁘다는 말~~

  

그래서 일부 키 입력은 기존에 작성 중인 임시 상태의 한글 입력을 취소시켜 버립니다. 이 글에서는 해당 신호들을 편의상 `문제 키`라는 표현으로 다루겠습니다.

  

- backspace
- 방향키
- cmd+e 같은 단축키
- 한영 전환
- 마우스 버튼

  

반면에 다음 입력 신호는 직전까지 작성한 자모 조합을 완성된 글자로 전환시킵니다. 이 글에서는 이를 `탈출 키`라고 표현하겠습니다.

  

- escape
- space
- enter
- tab
- 숫자 & 기호
- (다음 한글 자모)

  

단, 여기서 `enter` 키는 `탈출 키` 기능을 수행할 때 본연의 업무(줄바꿈)를 수행하지 않는 문제가 발생합니다.

  

결론적으로 한글 자모 입력 후 `문제 키` 와 `enter` 키 입력 이벤트가 발생했을 때 작성 중인 한글을 완성시키는 장치가 필요하다고 판단했습니다.

  

# 아이디어

  

Karabiner-Elements 는 키보드와 마우스 입력 신호를 조건에 따라(conditions) 다른 신호로 매핑해 주는 Complex modifications 기능을 제공하고 있으므로 이 방식을 사용했습니다. 비슷한 기능을 제공하는 다른 프로그램이나 내장 방식이 있다면 해당 방식을 사용해도 무방할 것입니다.

  

처음에는 모든 입력 신호를 감지하여 한글 자모와 그 외의 입력으로 구분하고, `문제 키` 직전의 최종 키가 한글이었는지 여부를 조사하여 그에 맞는 동작을 수행하게 할까 생각해 보았습니다. 하지만 Karabiner-Elements 에서 제공하는 방식으로는 json 코드만 수천 줄을 넘기도 하고 조건 구문도 많아져 키 입력 딜레이가 발생할 수 있다는 부분 때문에 포기했습니다. 다만 아래의 시행착오를 거친 후 결국 이 방법을 선택하게 되었습니다.

  

## 1. 시행착오 1

  

처음으로 시도한 것은 `문제 키`들이 입력되는 순간에 esc 키를 먼저 입력하여 작성 중인 자모 조합이 완성된 문자가 되도록 하는 간단한 아이디어였습니다.

  

```json
{
  "title": "이클립스 한글 짤림 해결",
  "rules": [
    {
      "description": "이클립스_백스페이스",
      "manipulators": [
        {
          "type": "basic",
          "from": {
            "key_code": "delete_or_backspace"
          },
          "parameters": {
            "basic.to_if_held_down_threshold_milliseconds": 10
          },
          "conditions": [
            {
              "type": "frontmost_application_if",
              "bundle_identifiers": [
                "^org\\.eclipse\\.platform\\.ide$"
              ]
            },
            {
              "type": "input_source_if",
              "input_sources": [
                {
                  "language": "^ko$",
                  "input_source_id": "^com\\.apple\\.inputmethod\\.Korean\\.2SetKorean$"
                }
              ]
            }
          ],
          "to": [
            {
              "key_code": "escape"
            }
          ],
          "to_after_key_up": [
            {
              "key_code": "delete_or_backspace"
            }
          ],
          "to_if_held_down": [
            {
              "key_code": "delete_or_backspace",
              "halt": true
            }
          ]
        }
      ]
    }
  ]
}
```

  

코드 일부를 간단히 설명하자면

  

- conditions(조건) - 입력 소스가 한글이고, 최상단 앱이 이클립스 일 경우에
- from(입력 받은 키값) - backspace 가 입력되면
- to(변경할 키값) - esc + backspace 로 입력을 전환

  

하는 간단한 내용으로 이루어져있다.

  

enter, tab, space 키들은 경우에 따라 작성한 코드가 변형(줄바꿈, 들여쓰기, 띄어쓰기)될 수 있기 때문에 가장 리스크가 덜한 것이 esc 키 였지만 이마저도 문제점이 있었다. 바로 클래스 생성과 같은 창과 상단 메뉴, 팝업 등에서 esc 키가 입력되어 창이 종료되는 문제가 발생했고 이것도 자주 겪으니 불편하기 짝이없었다.

  

추가적으로 한글 입력을 하지 않았더라도 시스템 입력 소스가 한글이면 무조건 동작하기 때문에 예상치 못한 문제가 지속적으로 발생하는 문제점도 있었습니다.

  

## 2. 시행착오 2

  

1번에서 시도한 방식에서 esc 키를 `Caps Lock` 키 2회 반복으로 변경해 보았습니다. 맥에서는 자체적으로 `Caps Lock` 키를 한영 전환키로 사용할 수 있는 기능이 있는데, 이를 이용해 입력 소스를 전환하면 작성한 글이 짤리지 않습니다.

  

![](https://i.imgur.com/MQBmYxX.png)

  

`Caps Lock` 키를 이용하면 작성하던 코드가 훼손되지 않고 팝업이나 메뉴 창이 의도치 않게 꺼지는 현상도 막을 수 있습니다. 다만 키 입력 딜레이가 너무 큽니다(0.4초 정도). 딜레이를 줄이면 정상적으로 동작하지 않았고, 그만큼 부자연스러움이 커지는 문제가 발생했습니다.

  

또한 키 조합 상황에서는 동작하지 않는다는 단점도 존재했습니다. cmd + s, shift + 방향키 등 키를 누른 상태에서는 `Caps Lock` 키가 동작하지 않았습니다.

  

```json
"key_code": "caps_lock",
"hold_down_milliseconds": 200
```

  

## 3. 잠정적 결론

  

처음에 무리한 시도라고 생각했던 모든 키의 입력을 받아 처리하는 방식을 선택했습니다. (적어도 제 수준에서는 이것이 가장 우아한 방법이라고 생각합니다.) 우려했던 딜레이 발생 같은 상황은 나타나지 않았고, 긴 코드 작업도 python 반복문으로 해결했습니다.

  

이 방식이 불가피하다고 판단한 사유는 다음과 같다.

  

- karabiner 만으로는 이클립스 내부의 어떤 창에 현재 포커스가 잡혀 있는지 확인할 수 없습니다. 에디터, 콘솔, 네비게이터, 메뉴창 등 작업에 따라 서로 다른 조건을 부여할 수 없습니다. (메뉴창에서만 esc 키 대신 다른 방법을 쓰면 되지 않냐는 접근이 통하지 않는다는 의미입니다.)
- 직전 입력 신호가 한글 키일 때만 동작을 수행하려면 모든 키 입력 감지가 불가피합니다.

  

위의 두 가지 사유를 해결할 수 있는 솔루션이 있다면 좀 더 간결한 방법이 나올 수 있을 것입니다.

  

방식을 간단하게 설명하자면, 우선 입력 신호를 한글 키, 영문 키 및 `탈출 키`, `문제 키`의 세 분류로 나누었고 신호가 입력될 때 아래와 같은 로직을 수행합니다.

  

- 한글 키가 입력될 경우 변수를 1로 저장합니다.
- 영문 키 및 `탈출 키`가 입력될 경우 변수를 0으로 저장합니다.
- `문제 키`가 입력될 경우에는 변수가 1일 때만 space + backspace 조합으로 한글을 완성시키고 변수를 0으로 저장합니다.

  

코드는 5,000줄 가량 되므로 아래의 깃허브 링크로 대체했습니다.

## 4. Karabiner-Elements 설치

## 5. .json 파일 다운로드

  

.json 파일은 [여기](https://github.com/taedi90/eclipse_kor_fix/releases)에서 다운로드할 수 있습니다.

json 파일을 생성할 때 사용한 python 코드도 함께 확인할 수 있습니다. (json 라이브러리도 있었지만 그냥 raw 텍스트로 작업했습니다.)

  
  
아래 경로에 다운로드 받은 .json 파일을 위치시킨다.  

> ~/.config/karabiner/assets/complex_modifications

  

## 6. 설정 추가

  

Karabiner-Elements Preferences > Complex modifications 탭에서 필요한 규칙들을 추가하면 됩니다. 기존에 다른 규칙들을 사용하고 있는 경우 정상적으로 작동하지 않을 수 있으므로 상단으로 올려 우선순위를 높이면 됩니다.

Karabiner-Elements Preferences > Devices 에서 사용하는 마우스가 체크되어 있는지 확인해야 합니다.

# 현재까지 발견 된 문제점

현재까지 발견한 문제는 다음과 같으며, 이 밖에도 다른 문제가 있을 수 있으니 유의하시길 바랍니다.

1. 한글 입력 직후 빠르게 cmd + s 등의 키 조합을 사용하려 할 경우 올바르게 동작하지 않는 현상입니다.  
      
    _cmd 키를 누르고 0.2초 이상 지난 후에 s 버튼을 눌러야 정상적으로 동작합니다._
2. 한글 입력 중 backspace 를 누르면 '종성' - '중성' - '초성' 순으로 지워지는 것이 아니라 한 글자가 바로 삭제되는 현상입니다. _2021.10.17 추가 내용 참고_
      
    

그리고 최고의 해결책은 이클립스를 포기하고 `intellij` 를 사용하는 것입니다.
